GitHub Pages 是怎么工作的

教程

把文件推上去，等一会儿，网址就能访问了。看起来像魔法，其实只有三步：GitHub 收到文件 → 构建（可选）→ 把文件摆到 CDN 上。

一、仓库名决定网址

  • 用户站点：仓库叫 用户名.github.io，网址就是 https://用户名.github.io
  • 项目站点：仓库叫别的名字，网址是 https://用户名.github.io/仓库名，一个账号可以有无数个

注意必须是公开仓库：免费账号的 Pages 只支持 public 仓库。站点本身也一定是公开可访问的，所以别放密钥、别放私人照片。

二、发布源：分支还是 Actions

在仓库的 Settings → Pages 里选发布源：

  1. Deploy from a branch：最简单，选分支和目录，每次推送自动发布
  2. GitHub Actions：适合需要构建的项目（Hugo、Astro、Next.js 静态导出……）

选分支方式时，GitHub 默认会拿 Jekyll 过一遍你的文件。纯手写的 HTML 站点建议在根目录放一个空的 .nojekyll 文件，跳过这层处理。

三、几个一定会踩的坑

  • 大小写：Pages 跑在 Linux 上，文件名区分大小写
  • 入口文件：根目录必须有 index.html，否则打开是 404
  • 路径：项目站点在子路径下，用相对路径最稳
  • 延迟：推送后最长要等约 10 分钟
  • 不能跑后端：PHP、Python、数据库都不行

四、本地预览

python -m http.server 8000
# 然后打开 http://localhost:8000

五、免费的边界

软限制大约是：仓库 1 GB，站点 1 GB，每月 100 GB 流量，每小时 10 次构建。个人主页和博客基本碰不到，别拿它当图床或者放视频就行。
